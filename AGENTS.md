# Cross-Embodiment CL

- Keep changes focused and follow existing local conventions.
- For Isaac-specific implementation work, use the adjacent `../IsaacLab/` checkout as the source reference; consult its `AGENTS.md` and `skills/` directory before making those changes.
- **Worktree location:** use the VS Code-style repository-local layout for new linked worktrees: `.worktree/<branch-name>/`. Do not create them in sibling or ad hoc directories.
- **Worktree includes:** treat `.vscode/settings.json` `git.worktreeIncludeFiles` as the authoritative copy list. VS Code copies these ignored files and folders when it creates a worktree; when using another worktree-creation method, copy the same paths from the primary checkout into the new worktree, preserving their repository-relative paths. Do not copy other ignored state implicitly.
- **Worktree execution:** a linked worktree may not have its own ready venv. Reuse the sibling main checkout's prepared venv, while making the active worktree's source authoritative: `PYTHONPATH=$PWD/src ../Cross-Embodiment-CL/.venv/bin/python <script>` or `PYTHONPATH=$PWD/src ../Cross-Embodiment-CL/.venv/bin/isaaclab <command>`. Do not use `uv run` from a worktree merely to run an existing Isaac command: it may create and populate a separate venv, including large CUDA packages.
- Any command that references a specific policy checkpoint must use its absolute/full filesystem path, never a relative path.
- **Isaac Lab CLI discovery:** before claiming a command is unavailable or inventing a wrapper, query the executable that will actually run it: `../Cross-Embodiment-CL/.venv/bin/isaaclab --help` followed by `../Cross-Embodiment-CL/.venv/bin/isaaclab <command> --help`. In particular, the built-in `zero_agent` command runs an environment with zero actions; use it for interactive manual scene inspection rather than adding a custom zero-action script.

## Test value policy

- Do not add a test unless it is genuinely valuable and catches a concrete, plausible regression. Tests must never be written merely for the sake of having a test, increasing coverage, mirroring a code change, or satisfying a routine expectation that every change gets a test.
- Valuable tests name a concrete failure mode and exercise observable behavior, integration or wiring, boundary/error handling, or comparison against an independent source of truth.
- Do not add tests that merely mirror implementation literals or defaults, assert private structure or ownership without an observable consequence, or duplicate dimensions/defaults already exercised by a stronger test. For configuration changes, prefer resolver or runtime effects; for assets, compare against authored or official sources. If no meaningful failure mode exists, do not add a test.
- Do not delete existing high-value tests merely because they include constants.

## Commit policy

- When working interactively with the user, keep changes as local unstaged and uncommitted diffs by default. Commit only when the user explicitly asks to commit; a prior commit request applies only to the changes current at that time and is not blanket permission for later commits.
- When working autonomously on an explicitly delegated end-to-end task, incremental focused commits are allowed.
- Before every commit, stage only the intended files, run the configured pre-commit hooks against the staged changes, resolve any failures, inspect the staged diff, and never bypass hooks with `--no-verify`.

## G1 + Wuji tabletop DirectRL environment

- The active task is `CrossEmbodimentCl-G1-Wuji-Table-Direct`, implemented under `src/Cross_Embodiment_CL/tasks/g1_wuji_table_direct/`.  Keep it a small privileged-state Stage-1 task: one fixed-base G1/Wuji, one YCB apple, one table; do not import legacy curriculum, vision, IK, or domain-randomization machinery without an explicit request.
- Robot configuration lives in `assets/g1/g1.py`: retain a shared `G1_BASE_CFG` and have hand variants derive from it.  `G1_WUJI_CFG.spawn.activate_contact_sensors` must remain enabled: the hand and torso contact sensors otherwise cannot initialize.
- Assets are deliberately normal Git blobs, including robot/hand USD layers and the latent checkpoint.  Do not reintroduce Git LFS filters for asset or model file types: fresh server clones must launch without Git LFS installed.
- The environment must remain backend-agnostic.  Launch PhysX or Newton through Isaac Lab CLI physics overrides rather than branching/hardcoding a backend in task code.  Always run runtime tests headless unless the user explicitly asks to see a viewer.
- Newton-specific constraints: keep Newton solver debug logging disabled (`debug_mode=False`), since its per-step Warp device-to-host debug readback previously caused CUDA illegal-memory-access failures.  Keep the configured per-environment contact capacities; total memory scales with environment count.  Newton ignores PhysX-only `max_contact_data_count_per_prim` with a harmless warning.
- The apple render mesh needs Newton visual-shape loading; its collision mesh alone is not a visible apple. Newton's runtime `convexDecomposition` calls CoACD with `merge=False`, so its hull cap is a no-op in practice (the apple produced ~58-61 hulls). Build reviewed offline colliders instead: add `collision_spec.json` next to an object's `textured.usda`, then run `uv run python scripts/make_object_decomposition.py assets/objects/<Object>`. The script uses CoACD with merge and decimation enabled, extrusion off, a 64-vertex cap (matching Newton's import limit), and writes `textured_collision.usda` with explicit collision-enabled hull prims. `mode: "hull"` produces one hull for near-convex objects; `mode: "coacd"` uses the optional `threshold` for concave objects. Get user visual sign-off for every generated asset before using it in debugging or training. The default `mesh_approximation_name="convexHull"` remains safe because Isaac Lab and Newton process each collision-enabled Mesh prim independently, never merging the already-authored hulls.
- The G1 is fixed-base.  Waist joints are held at zero internally; actions are 7 arm coordinates plus an 18-D Wuji latent.  The latent path is encoder/decoder plus retargeting, and the control state includes the post-EMA, speed-capped physical targets (arm EMA 0.25, hand EMA 0.1).
- Keep initial actuator limits intentional: arm K/D 300/30, 1.5 rad/s; arm efforts are the canonical Unitree G1 limits (unitree_mujoco `g1_29dof.xml`, equal to the G1 USD's maxForce): shoulder, elbow, and wrist roll 25 N·m, wrist pitch and yaw 5 N·m.  Hand drives are authored explicitly in the `wuji_fingers` actuator, 0.7 rad/s: effort limits (0.15-0.65 N·m) and K/D (2.0/1.0/0.8 N·m/rad by joint index, D 0.05/0.03) copy the hand USD's authored drives, whose `maxForce` equals the official wuji-hand-description MJCF; armature is the MJCF's (0.0005 on each joint1 and the thumb joint2, else 0.0002), since the USD authors none and an unset armature loads 0.  `tests/test_wuji_drive_cfg.py` pins them to the USD.  Commanded hand targets never go below 0 rad (the thumb base's limit is already 0.0475 rad), except the four fingers' symmetric side-swing `joint2`; the simulated joints keep their full limits, because the real hand can be pushed backwards.  Use Isaac Lab actuator target-command APIs, not deprecated direct target-tensor wrappers.
- Joint speed is capped in the task, because solver limits are not portable: `arm_joint_velocity_limit` 0.25 rad/s and `hand_joint_velocity_limit` 0.5 rad/s limit the per-policy-step change of the post-EMA targets, and `_apply_action` spreads that change evenly over the physics substeps so the drives track a ramp rather than a staircase.  Targets may lead the measured joint position by at most `(effort limit + damping * cap) / stiffness`, taken from the actuator cfg, so a blocked joint cannot wind its target up and snap back once released.  Do not write the caps into `joint_velocity_limit`: MJWarp ignores it, and a PhysX clamp at the cap blocks catch-up motion that Newton allows.  The solver keeps the asset's authored limits, and the joint-velocity observation is scaled by the caps directly.  A ramp-slope velocity feedforward is left commented in `_apply_action`: its gain is small at these speeds, and the real Wuji client takes position targets only.  Expect transient overshoot above the caps, mostly under contact.
- Contact/termination semantics are deliberately narrow: only apple-to-`g1_simplified/torso_link` terminates, not arm/torso self-contact.  Newton requires this full prim path; an abbreviated torso path matched no bodies.  Other failures are apple below table height or farther than 20 cm horizontally from its spawn.
- Observations are 171-D privileged state for both actor and critic, but their values intentionally differ under sensor-noise ADR: the actor/policy receives noisy joint positions, joint velocities, and object position, while the critic always receives the corresponding clean simulator-derived values. Physical DR (spawn, robot pose, friction, and mass) changes the simulation itself and therefore remains visible to both. Preserve action/controller state, robot state, object/goal pose and velocity, and compact contact magnitudes. Joint positions and the appended arm/hand `[lower, upper]` limit pairs are raw radians; velocities and commanded targets remain normalized. Wuji limits are the effective command limits: non-side-swing lower bounds are floored at 0 rad, the thumb retains its slightly positive asset limit, and the four symmetric side-swing joints retain their negative range. A separate `student` group carries only the 141-D actor/proprioceptive prefix (including actor sensor noise) for distillation; keep it a prefix of the actor observation. Episode metrics go in `extras["log"]`; reward components are already available from RSL-RL.
- Log tags follow `Group/<quantity>_<qualifier>_<timescale>` with the quantity first (`keypoint_error_ep_min`, not `min_keypoint_error`), so TensorBoard's alphabetical sort keeps related tags adjacent.  Groups: `Task` (success, keypoint error, object height), `Reach` (hand distances), `Contact`, `Reward` (per-term), `Control`, `Terminations`.  The timescale is always last: `step`, `ep` (mean), `ep_min`, `ep_max`, `ep_final`, `ep_return` (sum); fractions are `frac`.  `Reach/hand_distance_farthest_*` is the farthest of the six hand points (what the reach reward uses), `hand_distance_nearest_*` the nearest.  When renaming a tag, add the old name to `LEGACY_TAGS` in `scripts/run_summary.py`.  `Contact/penetration_{hand,table}_*` (deepest apple contact per environment, in metres) reads the MJWarp contact buffer, because contact sensors report no depth; it is logged only on Newton MJWarp and untested on PhysX.  `Contact/penetration_self_*` and `Contact/self_penetrating_frac_step` extend the same probe to the deepest hand-hand or hand-to-other-robot-geom (arm/torso) penetration, with the fraction over envs deeper than 0.5 mm; a pair the solver filters out of collision never appears in the buffer.
- Debug keypoint markers are non-colliding spheres and off for the headless `presets=train|eval` runs and on otherwise.  Goal/current pose markers are green/red respectively; toggle them with `env.debug.keypoint_markers`.  Viewer presets also draw the configured full-strength ADR spawn area as a thin, non-colliding blue square on the table even when ADR is inactive, so nominal-checkpoint playback still shows the randomization range; toggle it with `env.debug.adr_spawn_area_marker`.
- Launch settings are bundled as run presets in `env_cfg.py`, selected with `presets=train|debug|eval`: the default is MJWarp with 1 environment, the `newton_gl` viewer, keypoint markers, and Newton visual shapes; `train` (2048 environments) and `eval` (16, for headless eval-time success analysis) drop the viewer, markers, and visual shapes, while `debug` only sets 4 environments.  Because the default opens a viewer, headless runtime checks without `presets=train|eval` must pass `--viz none` or clear `sim.visualizer_cfgs`.  Add new per-mode settings as preset alternatives rather than launch flags, and put them on a section, never on a scalar field someone may override: Isaac Lab reads `env.a.b=value` on a preset node as a preset name, so a scalar preset turns `env.a.b=True` into an "Unknown preset" error.  CLI flags, `env.sim.physics=NAME`, and scalar overrides inside a selected section still win; `physics=` conflicts with `train` and `eval`, which pick their own headless physics config.  `tests/test_run_presets.py` pins the bundles.
- First training smoke: `uv run isaaclab train --rl_library rsl_rl --task CrossEmbodimentCl-G1-Wuji-Table-Direct --num_envs 2048 --device cuda --max_iterations 1 --run_name g1_wuji_table_2048_smoke`; omit `--max_iterations` only after that succeeds.  The initial RSL-RL MLP is intentionally large: `2048 -> 1024 -> 512`.
- Before declaring a change runnable, use focused headless tests plus `uv run ruff check src/Cross_Embodiment_CL/tasks/g1_wuji_table_direct tests/test_wuji_latent_round_trip.py`.  Test both PhysX at a meaningful environment count and Newton separately; a local 6 GB GPU only established Newton at 32 environments, not a 2048-env Newton guarantee.
- Defaults are `agent.algorithm.entropy_coef=0.005` and the gravity curriculum (`env.gravity_curriculum_start=0.0`, `env.gravity_curriculum_steps=19_200`, full gravity by iteration 600). Evaluation must always run at full gravity; `scripts/eval_policy.py` forces the curriculum off regardless of the training default.
- `env.reward_mode` switches the whole reward function between `"shaped"` (default: today's reach + contact-gated goal + lift + binary contact, with the press guard) and `"adept"`, an ADEPT-style minimal reward: reach, plus a goal term gated on the thumb and any other finger (never the palm) each exceeding `adept_gate_force` (1.0 N), with the goal term's keypoint-error sharpness ramping from `adept_goal_alpha_start` (15.0) to `adept_goal_alpha_end` (30.0) over `adept_goal_alpha_steps` (32 000 env steps, iteration 1000), plus a flat `adept_contact_reward_scale` (0.01) bonus under the same gate -- no lift term, no shaped contact term, no press guard. `"shaped"` stays the default until `"adept"` is shown to train. `adept_lift_reward_scale` (0.0 by default) optionally adds the shaped mode's dense `lift_fraction` term to `"adept"`, since the gated goal term alone gives no gradient toward lifting while far from the goal.
