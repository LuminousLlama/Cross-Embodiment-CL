# Cross-Embodiment CL

- Keep changes focused and follow existing local conventions.
- For Isaac-specific implementation work, use the adjacent `../IsaacLab/` checkout as the source reference; consult its `AGENTS.md` and `skills/` directory before making those changes.
- **Worktree location:** use the VS Code-style repository-local layout for new linked worktrees: `.worktree/<branch-name>/`. Do not create them in sibling or ad hoc directories.
- **Worktree includes:** treat `.vscode/settings.json` `git.worktreeIncludeFiles` as the authoritative copy list. VS Code copies these ignored files and folders when it creates a worktree; when using another worktree-creation method, copy the same paths from the primary checkout into the new worktree, preserving their repository-relative paths. Do not copy other ignored state implicitly.
- **Machine-local configuration:** `.local_untracked/` belongs only in the primary checkout. From any linked worktree, resolve the primary path with `git worktree list --porcelain` and read or write `<primary>/.local_untracked/`; never create a worktree-local copy. This keeps server profiles and queues shared across every worktree.
- **Primary versus linked-worktree execution:** first identify the checkout when it is not already clear. `git rev-parse --show-toplevel` gives the active checkout, while the parent of `git rev-parse --path-format=absolute --git-common-dir` is the primary checkout.
  - In the primary checkout, use normal commands such as `uv run python ...`, `uv run pytest ...`, and `uv run isaaclab ...`. This checkout owns the prepared `.venv` and is where dependency synchronization belongs.
  - In a linked worktree, run the same commands through `./worktree-local uv run ...`. The launcher reuses the primary checkout's prepared `.venv` without synchronizing it and makes the linked worktree's `src/` authoritative. Do not use bare `uv run` in a linked worktree: it may create and populate another environment, including large CUDA packages, or import the primary checkout's package instead.
  - If dependencies change, synchronize the primary checkout explicitly first; the linked-worktree launcher deliberately sets `UV_NO_SYNC=1` and must not modify the shared environment.
- Any command that references a specific policy checkpoint must use its absolute/full filesystem path, never a relative path.
- **Isaac Lab CLI discovery:** before claiming a command is unavailable, query the executable that will actually run it: `uv run isaaclab --help` followed by `uv run isaaclab <command> --help` in the primary checkout, or the same commands prefixed with `./worktree-local` in a linked worktree. In particular, the built-in `zero_agent` command runs an environment with zero actions; use it for interactive manual scene inspection rather than adding a custom zero-action script.
- **Command reference:** use `COMMANDS.MD` as the human-facing reference when running project workflows, and update it whenever supported options, presets, or recommended commands change. Keep it concise and command-focused, with minimal commentary; do not turn it into general documentation or bloat it with uncommon variants.

## Test value policy

- Do not add a test unless it is genuinely valuable and catches a concrete, plausible regression. Tests must never be written merely for the sake of having a test, increasing coverage, mirroring a code change, or satisfying a routine expectation that every change gets a test.
- Valuable tests name a concrete failure mode and exercise observable behavior, integration or wiring, boundary/error handling, or comparison against an independent source of truth.
- Do not add tests that merely mirror implementation literals or defaults, assert private structure or ownership without an observable consequence, or duplicate dimensions/defaults already exercised by a stronger test. For configuration changes, prefer resolver or runtime effects; for assets, compare against authored or official sources. If no meaningful failure mode exists, do not add a test.
- Do not delete existing high-value tests merely because they include constants.

## Commit policy

- When working interactively with the user, keep changes as local unstaged and uncommitted diffs by default. Commit only when the user explicitly asks to commit; a prior commit request applies only to the changes current at that time and is not blanket permission for later commits.
- When working autonomously on an explicitly delegated end-to-end task, incremental focused commits are allowed.

### Pre-commit workflow

- Only after a commit is authorized, stage the intended files explicitly and run hooks against those staged changes: `uv run pre-commit run` in the primary checkout or `./worktree-local uv run pre-commit run` in a linked worktree.
- If a hook modifies files, review the edits, restage only the intended files, and rerun the hooks until they pass. Then inspect `git diff --cached` before committing.
- Do not use `pre-commit run --all-files` for a focused change because formatting hooks may alter unrelated files. Never bypass hooks with `--no-verify`.

## G1 + hand tabletop DirectRL environment

- The active task is `CrossEmbodimentCl-G1-Hand-Table-Direct`, implemented under `src/Cross_Embodiment_CL/tasks/g1_hand_table_direct/`. Each environment contains one fixed-base G1 with the selected `wuji`, `inspire`, or `dex3` hand, one object, and one table. Select the homogeneous hand with `env.hand_type` and the object-bank subset with `env.active_objects`; only `YcbApple` is active by default.
- Robot configuration lives in `assets/g1/g1.py`: retain a shared `G1_BASE_CFG` and have hand variants derive from it. Contact sensors must remain enabled on every hand variant's spawn configuration so the hand and torso sensors can initialize.
- Assets are deliberately normal Git blobs, including robot/hand USD layers and the latent checkpoint.  Do not reintroduce Git LFS filters for asset or model file types: fresh server clones must launch without Git LFS installed.
- The environment must remain backend-agnostic.  Launch PhysX or Newton through Isaac Lab CLI physics overrides rather than branching/hardcoding a backend in task code.  Always run runtime tests headless unless the user explicitly asks to see a viewer.
- Newton-specific constraints: keep Newton solver debug logging disabled (`debug_mode=False`), since its per-step Warp device-to-host debug readback previously caused CUDA illegal-memory-access failures.  Keep the configured per-environment contact capacities; total memory scales with environment count.  Newton ignores PhysX-only `max_contact_data_count_per_prim` with a harmless warning.
- The apple render mesh needs Newton visual-shape loading; its collision mesh alone is not a visible apple. Newton's runtime `convexDecomposition` calls CoACD with `merge=False`, so its hull cap is a no-op in practice (the apple produced ~58-61 hulls). Build reviewed offline colliders instead: add `collision_spec.json` next to an object's `textured.usda`, then run `uv run python scripts/make_object_decomposition.py assets/objects/<Object>`. The script uses CoACD with merge and decimation enabled, extrusion off, a 64-vertex cap (matching Newton's import limit), and writes `textured_collision.usda` with explicit collision-enabled hull prims. `mode: "hull"` produces one hull for near-convex objects; `mode: "coacd"` uses the optional `threshold` for concave objects. Get user visual sign-off for every generated asset before using it in debugging or training. The default `mesh_approximation_name="convexHull"` remains safe because Isaac Lab and Newton process each collision-enabled Mesh prim independently, never merging the already-authored hulls.
- The G1 is fixed-base. Waist joints are held at zero internally; actions are 7 arm coordinates plus a shared 18-D hand latent. The latent path is encoder/decoder plus hand-specific retargeting, and the control state includes the post-EMA, speed-capped physical targets (arm EMA 0.25, hand EMA 0.1).
- Keep actuator limits intentional: arm K/D 40/10, authored speed limit 1.5 rad/s; arm efforts follow the canonical Unitree G1 limits: shoulder, elbow, and wrist roll 25 N·m, wrist pitch and yaw 5 N·m. Wuji's explicit `wuji_fingers` drives copy the hand USD's effort and K/D values, with official MJCF armature; `tests/test_wuji_drive_cfg.py` verifies them against the asset. Inspire and Dex3 inherit their authored USD drives. Command lower floors come from each hand's registry; simulated joints retain their full asset limits. Use Isaac Lab actuator target-command APIs, not deprecated direct target-tensor wrappers.
- Joint speed is capped in the task, because solver limits are not portable: `arm_joint_velocity_limit` 0.25 rad/s and `hand_joint_velocity_limit` 0.5 rad/s limit the per-policy-step change of the post-EMA targets, and `_apply_action` spreads that change evenly over the physics substeps so the drives track a ramp rather than a staircase.  Targets may lead the measured joint position by at most `(effort limit + damping * cap) / stiffness`, taken from the actuator cfg, so a blocked joint cannot wind its target up and snap back once released.  Do not write the caps into `joint_velocity_limit`: MJWarp ignores it, and a PhysX clamp at the cap blocks catch-up motion that Newton allows.  The solver keeps the asset's authored limits, and the joint-velocity observation is scaled by the caps directly.  A ramp-slope velocity feedforward is left commented in `_apply_action`: its gain is small at these speeds, and the real Wuji client takes position targets only.  Expect transient overshoot above the caps, mostly under contact.
- Contact/termination semantics are deliberately narrow: only object-to-`g1_simplified/torso_link` contact terminates, not arm/torso self-contact. Newton requires this full prim path; an abbreviated torso path matched no bodies. Other failures are an object below table height or non-finite simulation state. The optional 20 cm horizontal workspace termination is disabled by default.
- The actor receives 191-D privileged state; the critic receives 267-D clean state including 76-D DR information. Actor joint positions, joint velocities, and object position include configured sensor noise; the critic uses clean simulator values. Both see physical DR. Hand state uses 20 semantic slots plus a 20-D presence mask, with absent slots zeroed. Preserve action/controller state, robot state, object/goal pose and velocity, and compact contact magnitudes. Joint positions and `[lower, upper]` limit pairs are raw radians; velocities and commanded targets remain normalized. Effective hand command limits apply the selected hand's lower floors without changing simulated joint limits. The `student` group is the 161-D actor/proprioceptive prefix, including sensor noise and the hand mask. Episode metrics go in `extras["log"]`; reward components are available from RSL-RL.
- Log tags follow `Group/<quantity>_<qualifier>_<timescale>` with the quantity first (`keypoint_error_ep_min`, not `min_keypoint_error`), so TensorBoard's alphabetical sort keeps related tags adjacent.  Groups: `Task` (success, keypoint error, object height), `Reach` (hand distances), `Contact`, `Reward` (per-term), `Control`, `Terminations`.  The timescale is always last: `step`, `ep` (mean), `ep_min`, `ep_max`, `ep_final`, `ep_return` (sum); fractions are `frac`.  `Reach/hand_distance_farthest_*` is the farthest of the configured palm and fingertip points (what the reach reward uses), `hand_distance_nearest_*` the nearest.  When renaming a tag, add the old name to `LEGACY_TAGS` in `scripts/run_summary.py`.  `Contact/penetration_{hand,table}_*` (deepest object contact per environment, in metres) reads the MJWarp contact buffer, because contact sensors report no depth; it is logged only on Newton MJWarp and untested on PhysX.  `Contact/penetration_self_*` and `Contact/self_penetrating_frac_step` extend the same probe to the deepest hand-hand or hand-to-other-robot-geom (arm/torso) penetration, with the fraction over envs deeper than 0.5 mm; a pair the solver filters out of collision never appears in the buffer.
- Debug keypoint markers are non-colliding spheres and off for the headless `presets=train|eval|distill` runs and on for the default and `debug` profiles. Goal/current pose markers are green/red respectively; toggle them with `env.debug.keypoint_markers`. Viewer profiles also draw the configured full-strength ADR spawn area as a thin, non-colliding blue square on the table even when ADR is inactive; toggle it with `env.debug.adr_spawn_area_marker`.
- Run settings are selected once at the root in `env_cfg.py`: the default is MJWarp with 1 environment, the `newton_gl` viewer, markers, and Newton visual shapes; `train` is 2048 environments headless without visual shapes; `debug` is 4 environments with the normal viewer and markers; `eval` is 16 environments headless without visual shapes; and `distill` is 1024 environments headless with the student depth camera and visual shapes. Compose these mutually exclusive profiles with independent `force`, `depth_view`, `dr_none`, and `dr_full` overlays, for example `presets=distill,force,dr_full` or `presets=debug,depth_view,force`. `force_distill` does not exist. Because the default opens a viewer, headless runtime checks without a headless profile must pass `--viz none` or clear `sim.visualizer_cfgs`. Use `physics=NAME` for an independent backend choice; explicit CLI flags and scalar overrides still win. Keep presets on config sections, never scalar fields, because Isaac Lab interprets an override of a preset node as a preset name. `tests/test_run_presets.py` pins these contracts.
- First training smoke: `uv run isaaclab train --rl_library rsl_rl --task CrossEmbodimentCl-G1-Hand-Table-Direct --num_envs 2048 --device cuda --max_iterations 1 --run_name g1_hand_table_2048_smoke`; omit `--max_iterations` only after that succeeds.  The initial RSL-RL MLP is intentionally large: `2048 -> 1024 -> 512`.
- Before declaring a change runnable, use focused headless tests plus `uv run ruff check src/Cross_Embodiment_CL/tasks/g1_hand_table_direct tests/test_hand_latent_round_trip.py`.  Test both PhysX at a meaningful environment count and Newton separately; a local 6 GB GPU only established Newton at 32 environments, not a 2048-env Newton guarantee.
- The default is `agent.algorithm.entropy_coef=0.001`. Gravity is controlled only by ADR: while ADR is enabled, `gravity_fraction = env.adr.gravity_start + (1 - env.adr.gravity_start) * adr_strength`; `env.adr.gravity_start` defaults to `0.0`. ADR-disabled runs use full gravity. Evaluation commands select `dr_full`, so they run at full gravity.
- `env.reward_mode` selects `"adept"` (default) or `"shaped"`. ADEPT rewards reach, a goal term gated on the thumb and another finger each exceeding `adept_gate_force` (0.3 N), and a flat gated contact bonus (0.01). Its goal sharpness follows ADR strength from 15.0 to 30.0. Shaped rewards reach, ungated goal progress, and a flat thumb-and-finger contact bonus. Optional lift is globally disabled by `lift_reward_enabled=False`; when enabled, each mode uses its own lift scale (`adept_lift_reward_scale=0.0`, `lift_reward_scale=3.0`).
